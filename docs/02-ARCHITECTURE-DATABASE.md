# Architecture and Database Specification

## 1. Architecture

Use a modular monorepo.

```text
                    ┌────────────────────┐
                    │     Next.js Web     │
                    │ Dashboard + API     │
                    └─────────┬──────────┘
                              │
                              ▼
                    ┌────────────────────┐
                    │ Neon PostgreSQL     │
                    │ pgvector            │
                    │ pg-boss             │
                    └─────────┬──────────┘
                              ▲
                              │
                    ┌─────────┴──────────┐
                    │ Background Worker  │
                    │                    │
                    │ ingestion           │
                    │ analysis            │
                    │ resume generation   │
                    │ browser automation  │
                    └──────┬───────┬─────┘
                           │       │
                           ▼       ▼
                       Gemini   Playwright
```

The web process must remain responsive. Long-running scraping, AI, PDF rendering, and Playwright work belongs in the worker.

## 3. Indexes

Create indexes on:

```text
jobs.company_id
jobs.source_id
jobs.posted_at
jobs.status
jobs.normalized_title
jobs.content_hash
job_analysis.track
job_analysis.fit_score
applications.status
applications.created_at
application_events.application_id
```

Use pgvector indexes appropriate to the selected embedding dimension and workload.

For v1, correctness is more important than premature vector-index optimization.

## 4. Domain states

A job should generally move:

```text
DISCOVERED
   ↓
FILTERED
   ↓
ANALYZED
   ↓
READY_FOR_REVIEW
```

Applications move independently:

```text
READY_FOR_REVIEW
   ↓
APPROVED
   ↓
PREPARING
   ↓
APPLYING
   ↓
SUBMITTED
```

Error paths:

```text
ANY → FAILED
ANY → NEEDS_HUMAN
```

Do not silently change states.

Add any email integration variables only when the email ingestion module is implemented.

## 7. Database safety

Use transactions for:

- job insertion + deduplication
- application state transitions
- approval + event creation
- submission + event creation

Every worker job must be idempotent.
